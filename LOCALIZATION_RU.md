# Локализация Ostranauts: техническое руководство и FAQ

[English version](LOCALIZATION_EN.md) · [README проекта](README.md) · [Глоссарий и стиль](script/stage3_glossary.md)

Этот документ предназначен для авторов локализаций Ostranauts. Он описывает не только перевод строк, но и границы между текстом и игровым поведением: в этой игре неверно изменённое поле JSON может оборвать сюжет, заблокировать туториал или отправить персонажа не в тот регион.

## Карта проекта

Локализация состоит из двух независимых слоёв:

| Слой | Где находится | Для чего нужен |
|---|---|---|
| Данные мода | `OstranautsVodkaEdition/data/**` | Диалоги, условия, описания, справочники, большинство строк интерфейса |
| Плагин BepInEx/Harmony | `BepInExPlugin/**` | Динамическая грамматика, обучение, текст внутри Unity-префабов и другие строки, недоступные через данные |

Перед началом работы нужны исходные данные той же версии игры. Для локальной установки проекта это обычно:

```text
Ostranauts_Data/StreamingAssets/data/
```

Правила русского стиля, обращений, имён и токенов собраны в [глоссарии](script/stage3_glossary.md). Для другой локали создайте собственный глоссарий, но не меняйте внутренние идентификаторы и токены.

## Безопасный рабочий цикл

1. Найдите соответствующую запись в оригинальных данных игры.
2. Сопоставьте объект с копией в моде по `strName`.
3. Переведите только видимые игроку поля, например `strTitle`, `strDesc`, `strTooltip`, `strNameFriendly`, `strNameShort`.
4. Сохраните все токены, теги, переносы и структуру записи.
5. Сравните мод с оригиналом структурно, просмотрите diff и проверьте результат в игре.

Нельзя заменять объект целиком подготовленной «переведённой» версией, если её структура не проверена против оригинала той же версии игры. В этом проекте уже пришлось восстановить **437 нетекстовых полей** после такого повреждения: JSON открывался, русский текст отображался, но пропадали сюжетные экраны, условия и достижения.

### Поля, которые нельзя переводить или менять без понимания кода

Следующие поля участвуют в поведении игры. Значения в них обычно должны совпадать с оригиналом:

- `strName` — внутренний ID записи;
- `aInverse` — переходы между действиями и сюжетными экранами;
- `CTTestUs`, `CTTestThem`, `ShipTestUs`, `ShipTestThem`, `LootCondsUs`, `LootCondsThem` — условия, проверки и выдача состояний;
- `strRaiseUI`, `strSubUI`, `bPause`, `strImage`, `strMusic` — отдельные сюжетные интерфейсы, иллюстрации, пауза и музыка;
- `strTutorialKey`, `strSetPlotObjective` — ключи обучения и целей;
- `strAchievementUnlock` — ID достижения;
- `strTeleportRegID`, `strTargetPoint`, `strThemType` — место назначения, тип цели и точка взаимодействия;
- пути ресурсов, имена префабов, коды регионов, enum-подобные значения и массивы ссылок.

Например, перевод `strTutorialKey` ломает поиск нужного шага обучения, а повреждённый `aInverse` может заменить следующий экран сюжета на `ENCFinish`. Не переводите и не локализуйте ID, коды и пути, даже если они выглядят как английские слова.

## Форматы данных и JSON

### Обычные записи

Большинство файлов — JSON-массив объектов. Используйте `strName` для сопоставления объекта оригинала и мода. Не удаляйте отсутствующие в оригинале модовые записи: это могут быть осознанные дополнения локализации.

### Плоские таблицы `aValues`

`strings.json` и некоторые файлы условий используют плоский массив `aValues`, где одно логическое правило хранится несколькими соседними элементами. В таких таблицах нельзя безопасно переставлять, удалять или вставлять элементы вручную: сохраните порядок, количество и все служебные ячейки. Меняйте только текстовое значение в известной позиции записи.

### Токены и грамматические таблицы

Файлы вроде `data/tokens/grammar.json` — не обычный текстовый словарь. В них важны ключи, порядок вариантов и синтаксис. Не заменяйте английский ключ токена русским словом без проверки поддержки в плагине.

### Почему строгий JSON-парсер может быть неверным инструментом

Оригинальные файлы игры не всегда являются строгим JSON для стандартной библиотеки Python: встречаются UTF-8 BOM, строковые `//`-комментарии, управляющие символы внутри строк и нестандартные escape-последовательности.

Для чтения и массовой обработки используйте функции из `script/ostranauts_tools/json_utils.py` и инструменты проекта, а не бездумный `json.load()`/`json.dump()`. Любой инструмент, который переписывает файлы, запускайте сначала на копии или отдельной ветке, затем проверяйте `git diff`.

## Токены, грамматика и разметка

Сохраняйте в точности:

- токены в квадратных скобках: `[us]`, `[them]`, `[us-obj]`, `[them-pos]`;
- глагольные токены, например `[watches]`, `[asks]`, `[hacks]`;
- HTML/TMP-разметку: `<b>`, `<color=...>`, `<size=...>`;
- переносы `\n`;
- маркеры обучения `{glyph:...}`;
- гендерные конструкции и число/порядок вариантов через `|`.

Для русской локализации предпочтительно оставлять английские глагольные токены: они являются наиболее надёжными ключами для грамматической обработки. Плагин добавляет русские формы через:

- `OstranautsVodkaEdition/data/tokens/grammar.json` — местоимения, падежи и служебная грамматика;
- `BepInExPlugin/verb_conjugations.json` — шесть форм глагола: 1/2/3 лицо, единственное/множественное число;
- `BepInExPlugin/Main.cs` — Harmony-патчи для выбора формы, родовых форм прошедшего времени и удаления английского `the`.

Не заменяйте глобально токен только потому, что он плохо звучит в одной реплике. Например, `[learns]` может в одних местах означать «учится», а в новостной реплике — «узнаёшь». В таких случаях меняйте конкретную фразу, не ломая другие контексты.

## Туториалы и текст, связанный с поведением

Текст обучающих целей хранится в `BepInExPlugin/tutorial_translations.json` и подставляется плагином. Маркеры `{glyph:...}` обязательны: плагин заменяет их на актуальные клавиши пользователя.

Никогда не используйте переведённую видимую надпись как условие выполнения. В этом проекте цель `RestoreNavStation` проверяется по стабильному внутреннему полю `strDuty == "Restore"`, а не по локализованному заголовку кнопки. Это общее правило для целей, условий, триггеров и переходов сюжета.

## Если строка не находится в JSON

Правильный перевод в данных может не появиться в игре, потому что текст бывает четырёх видов:

| Тип строки | Что делать |
|---|---|
| Данные мода | Найти запись в `OstranautsVodkaEdition/data/**` и перевести видимое поле |
| Код игры | Найти безопасную точку перехвата и добавить Harmony-патч |
| Текст внутри Unity-префаба | После `Awake`/инициализации найти `TMP_Text` через стабильный путь `transform.Find(...)` и заменить `.text` |
| Текст, перезаписываемый во время работы | Патчить конкретный метод обновления, а не только `Awake` |

Готовые примеры в `BepInExPlugin/Main.cs`:

- обучение и динамические цели;
- Escape-меню и индикатор последнего сохранения;
- Sink Mirror (`GUIChargenBody.Awake`);
- Career Kiosk (`GUIChargenCareer.Awake`);
- диалоговое окно и радиальное контекстное меню;
- приоритет модовых изображений справочника и таблиц override.

Пути `transform.Find(...)`, имена компонентов и сигнатуры методов зависят от версии игры. После обновления Ostranauts обязательно перепроверяйте их в игре и по логу BepInEx.

## Шрифты TextMeshPro

Если целевая локаль требует глифов, которых нет в шрифте игры, создайте `TMP_FontAsset` в рантайме и примените его только к нужным компонентам. В проекте `Montserrat-Bold.ttf` загружается рядом с DLL и применяется к диалогам и контекстному меню; оригинальный шрифт сохраняется fallback-ом.

Не распространяйте коммерческие шрифты без разрешения. Для упаковываемых вместе с модом шрифтов используйте лицензию, допускающую распространение, и кладите текст лицензии рядом с ассетом.

## Инструменты проверки

Указывайте явные пути, не полагайтесь на устаревшие значения по умолчанию:

```bash
# Статистика перевода и оставшиеся английские строки
python script/ostranauts_tools/translation_stats.py \
  --game-path "D:/SteamLibrary/steamapps/common/Ostranauts/Ostranauts_Data/StreamingAssets/data" \
  --mod-path "OstranautsVodkaEdition/data" \
  --sort-by remaining --top 20

# Токены, плейсхолдеры и подозрительно совпадающий с оригиналом текст
python script/audit_translation.py

# Структурная проверка мода; сначала только отчёт
python script/ostranauts_tools/validate_mod.py \
  --game-path "D:/SteamLibrary/steamapps/common/Ostranauts/Ostranauts_Data/StreamingAssets/data" \
  --mod-path "OstranautsVodkaEdition/data" --norus
```

`translation_stats.py` измеряет наличие кириллицы, а не качество перевода. `audit_translation.py` помогает найти пропуски токенов, но не заменяет ручное чтение и запуск игры. Перед использованием режимов, которые меняют данные (`--apply`, массовая инъекция или синхронизация), создайте резервную копию/ветку и просмотрите diff. Не используйте агрессивные режимы очистки, не убедившись, что они не удалят осознанные добавления локализации.

## Финальная проверка перед релизом

- [ ] Все изменённые JSON-файлы загружаются тем же tolerant-парсером, что используется инструментами проекта.
- [ ] В структурном сравнении нет отличий вне разрешённых текстовых полей.
- [ ] Сохранены все токены, теги, `\n`, `{glyph:...}` и варианты через `|`.
- [ ] Просмотрен `git diff`: нет случайных замен ID, условий, путей, массива `aInverse` или UI-полей.
- [ ] Мод запускается без ошибок загрузки данных.
- [ ] `BepInEx/LogOutput.log` содержит загрузку спряжений/обучения и применение Harmony-патчей.
- [ ] Проверены динамические местоимения и глаголы, шаг обучения, отдельный сюжетный экран и как минимум один экран с префабным текстом.
- [ ] Для новой версии игры проверены пути к префабам и точки Harmony-патчей.

## Что приложить к изменению

Для ревью укажите: версию игры, затронутые файлы и `strName`, выполненные команды проверки, результаты игрового smoke-теста и известные непроверенные сценарии. Небольшие, тематические diff-ы проверяются надёжнее массовых переформатирований.
